## 2026-11-17 后台死锁修复（本地 build 27）

现场线程采样确认：放电请求持有策略文件锁，SleepHoldController.acquire → SystemSleepControl.read → Foundation Process.waitUntilExit 驱动嵌套 RunLoop，15 秒定时器回调再次调用 Helper.run 并等待 flock，形成同线程自锁；另一个安装准备进程也在等待该锁。直接只读硬件确认原 80% 上限仍在、CHIE=0。用户明确授权后结束旧死锁与等待进程，恢复限充并安装 build 27；观察超过两个15秒检查周期后，心跳持续更新、后台无错误，安装组件哈希一致。

修复采用 posix_spawn、非阻塞管道和 waitpid(WNOHANG)，使用单调时钟限制等待时间与输出大小，失败时终止并回收子进程，不驱动后台主循环。57 项睡眠/进程检查、135 项策略检查、7 项适配器模拟及42项更新检查通过。真实 pmset -g 只读对照各30次：旧实现1927次嵌套回调，新实现0次；正常定时回调仍在操作返回后执行。未启动主动放电、未做真实睡眠唤醒或 XPC 全链路验证，不据此扩大功能验收范围。
